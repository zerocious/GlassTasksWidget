# Выпуск релиза

Релиз собирает GitHub Actions (`.github/workflows/release.yml`) и кладёт установщик в **черновик**
релиза. Пользователи с автообновлением видят только опубликованные релизы, поэтому у вас есть
время проверить установщик до того, как он до них дойдёт.

## Один раз перед первым публичным релизом

| Что | Зачем | Как |
|---|---|---|
| Публикация OAuth-приложения | в статусе **Testing** Google выдаёт refresh-токены на **7 дней**: вход слетает раз в неделю | Google Cloud → Google Auth Platform → **Audience → Publish app** |
| Страница политики конфиденциальности | Google требует её при публикации (в статусе Testing не нужна) | исходный репозиторий приватный, ссылка на него не откроется: выложите текст [`docs/PRIVACY.md`](docs/PRIVACY.md) в публичный репозиторий релизов и укажите ту ссылку на экране согласия (**Branding**) |
| Токен для канала обновлений | см. «Канал обновлений» ниже: без него workflow не создаст релиз | один раз, секрет `RELEASES_TOKEN` |
| Встроенный клиент (необязательно) | чтобы пользователи не заводили свой проект Google Cloud | см. «Свой клиент или встроенный» ниже |
| Подпись установщика (необязательно) | убирает предупреждение SmartScreen, включает проверку издателя при обновлении | сертификат подписи кода; без него `verifyUpdateCodeSignature` остаётся выключенным |

### Ограничения без проверки приложения Google

- Пользователи видят экран «Google не проверил это приложение» и проходят его через «Дополнительно».
- До **100 новых пользователей за всё время жизни проекта** (счётчик не сбрасывается). Для личного
  использования и знакомых этого достаточно; для публичной раздачи нужна проверка (домен,
  страница приложения, политика, видео, 3-10 рабочих дней). Аудит безопасности (CASA) для
  `auth/tasks` не нужен: scope не входит в список restricted.
- Пока клиент общий для всех, не коммитьте его секрет в открытый репозиторий (условия Google API).

## Канал обновлений

Исходный репозиторий `zerocious/GlassTasksWidget` **приватный**: установленный виджет не может читать
его релизы (GitHub отвечает 404), поэтому обновления раздаются из **публичного**
`zerocious/GlassTasksWidget-releases` (`build.publish` в `app/package.json`). Там уже лежит `v1.0.1`
из ветки `feature/work-hours-blocker`, поэтому версия каждого нового релиза должна быть **больше
1.0.1**, иначе electron-updater его не предложит.

Workflow создаёт черновик релиза в репозитории релизов, а `GITHUB_TOKEN` туда писать не может. Один раз:

1. GitHub → Settings → Developer settings → **Fine-grained tokens** → Generate: доступ только к
   `zerocious/GlassTasksWidget-releases`, разрешение **Contents: Read and write**.
2. В `zerocious/GlassTasksWidget` → Settings → Secrets and variables → Actions → New secret
   `RELEASES_TOKEN` с этим токеном.

## Выпуск

1. **Версия и журнал изменений.** В `CHANGELOG.md` перенесите раздел «Не выпущено» в новую версию.
   В `app/package.json` поднимите версию (`npm version 1.1.0 --no-git-tag-version` из папки `app`).
2. Влейте это в `main` через PR (CI: линт и тесты).
3. **Тег.** Он должен совпадать с версией:
   ```bash
   git tag v1.1.0
   git push origin v1.1.0
   ```
4. Workflow **Release** запустит линт, тесты, smoke-проверку пакета, соберёт установщик, проверит
   метаданные автообновления (`scripts/check-release.js`) и создаст **черновик релиза** в
   `GlassTasksWidget-releases`.
   Проверка метаданных ловит ошибки, из-за которых автообновление молча ломается: имя файла,
   размер, контрольная сумма, blockmap, адрес репозитория.
5. **Ручная проверка установщика** (обязательна, на чистой Windows или в виртуальной машине):
   - [ ] установка проходит, ярлыки на рабочем столе и в меню «Пуск» создаются;
   - [ ] первый запуск без ключей: мастер «Подключение Google» и демо-режим работают;
   - [ ] вход в Google: браузер открывается, после «Готово» задачи загружаются;
   - [ ] добавить задачу («завтра в 9:30»), отметить выполненной, перезапустить: данные на месте;
   - [ ] напоминание на ближайшую минуту приходит уведомлением Windows;
   - [ ] «Выйти» отзывает доступ (https://myaccount.google.com/permissions: приложения нет);
   - [ ] Настройки → «Скопировать отчёт»: отчёт собирается, в нём нет токенов;
   - [ ] **обновление:** установить предыдущую версию, опубликовать эту, дождаться предложения
     обновиться (или «Проверить обновления»), согласиться, убедиться, что данные сохранились.
6. **Опубликуйте черновик** («Publish release»). Только с этого момента его увидят пользователи.

### Если Actions недоступны (ручная сборка)

Из папки `app`, **не** через `npm run pack` / `dist` / `shortcut`: `prebuild-clean.ps1` завершает все
процессы «Glass Tasks Widget», а `shortcut` переписывает ярлыки на текущую сборку.

```bash
npm ci && npm run lint && npm test
CSC_IDENTITY_AUTO_DISCOVERY=false npx electron-builder --win nsis --x64 --publish never
node scripts/check-release.js dist
```

Создайте релиз в `zerocious/GlassTasksWidget-releases` (не в исходном репозитории) и загрузите **все три** файла: `Glass-Tasks-Widget-Setup-<версия>.exe`, `….exe.blockmap`,
`latest.yml`. Имя установщика без пробелов намеренно: GitHub заменяет пробелы точками, и ссылка в
`latest.yml` перестала бы работать.

## Откат

- До публикации: удалите черновик и тег.
- После публикации: unpublish релиза убирает его для новых проверок обновления. Уже
  обновившиеся пользователи на старую версию не вернутся (electron-updater не понижает версию):
  выпустите исправление с большей версией.

## Свой клиент или встроенный

Сейчас каждый пользователь заводит свой OAuth-клиент (мастер ведёт по шагам). Встроенный общий
клиент убирает этот шаг, но тогда на вас лежат ограничения из раздела выше. Если решите его
включить, ключи должны попадать в сборку из секретов CI, а не из репозитория.

## Что проверяет автоматика, а что нет

| Проверяется | Не проверяется |
|---|---|
| линт, тесты, упаковка, запуск пакета на чистом профиле (`npm run smoke:packaged`), fuses Electron, метаданные автообновления | сам установщик NSIS (установка, ярлыки, удаление), вход в настоящий аккаунт Google, обновление между версиями: это пункты ручной проверки выше |
