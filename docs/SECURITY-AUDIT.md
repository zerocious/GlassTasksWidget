# Аудит безопасности Glass Tasks Widget — октябрь 2026

Проверено состояние ветки `claude/relaxed-cori-wrn98v` (PR #14) поверх `claude/auth-onboarding`. Для каждой находки отдельно сверялась ветка `claude/prod-readiness`: что в ней уже исправлено, отмечено.

**Как проводился аудит.** Пять направлений: рендерер и окно, IPC главного процесса, OAuth/сеть/обновления, интеграция с Windows, хранилище данных. Каждую находку независимо проверял второй ревьюер, задача которого была её опровергнуть. Где можно, находки воспроизводились: скриптами Node и в Electron 33.4.11 под xvfb с теми же CSP и `webPreferences`, что у виджета.

## Модель угроз

| | Кто или что | Пример |
|---|---|---|
| T1 | Чужой текст в задачах | тема письма через Gmail «Добавить в Tasks», задача, назначенная из Google Docs/Chat |
| T2 | Веб-страница в браузере пользователя | обращения к loopback-серверу входа, DNS rebinding |
| T3 | Сеть или канал обновлений | MITM, подменённый релиз на GitHub |

| T6 | Вредонос под той же учётной записью | вне модели: ему доступно всё, что доступно пользователю |

## Итог

Критических находок нет. Путей XSS из текста задач в рендерере нет: все строки из Google попадают в DOM только через `textContent`/`value`. Окно настроено правильно: `sandbox`, `contextIsolation`, без `nodeIntegration`, `window.open` запрещён.

Самое серьёзное, что нашлось и исправлено:

- **Утечка refresh-токена в лог при неудачном выходе.** `revokeToken()` передавал токен в URL, а при сетевой ошибке текст ошибки с этим URL писался в журнал.
- **Подсунутый «экспорт» мог включить автозапуск, занять системные клавиши и раздуть историю привычек** (импорт).
- **Квадратичные регулярные выражения в разборе заметок.** Длинная строка пробелов в заметке задачи подвешивала главный процесс.

Остаток — укрепление в файлах других владельцев. Готовые исправления собраны ниже.

## Готовые исправления для владельцев файлов

**(1) CSP и подфреймы** (`src/index.html`, `electron/main.js`). Проверено в Electron 33: блокирует и чтение файлов через `fetch`, и обход через `<iframe>`/`<object>`. Шрифты и интерфейс работают.

```html
<meta http-equiv="Content-Security-Policy" content="default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'none'; frame-src 'none'; child-src 'none'; worker-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'" />
```

```js
mainWindow.webContents.on('will-frame-navigate', (d) => {
  if (!d.isMainFrame) d.preventDefault();
});
```

Полное решение — отдавать `src/` через свой протокол (`protocol.handle('app', …)` только для папки `src`), после чего выключить fuse `GrantFileProtocolExtraPrivileges` в `scripts/after-pack.js`. Тогда `'self'` перестанет означать «любой файл на диске». Проверку отправителя IPC в `main.js` стоит заменить на `isTrustedSender` из `electron/data-ipc.js`: главный фрейм и точный URL страницы.

**(2) DevTools в собранной программе.** До создания окна вызвать `Menu.setApplicationMenu(null)`, в `webPreferences` поставить `devTools: !app.isPackaged`, а `--dev` учитывать только при `!app.isPackaged`. От `--remote-debugging-port` в собранной программе можно отказаться через `app.exit(1)`, но на нём построен `scripts/smoke-packaged.js` из prod-readiness. Решайте вместе.

**(3) `openExternal`.** Пусть рендерер присылает ключ (`enableApi`, `branding`, `audience`, `clients`, `apiOverview`), а главный процесс строит URL из `CONSOLE_LINKS` в `lib/auth-errors.js`. Для `apiOverview` номер проекта проверяется по `^\d{4,}$`. Убрать `github.com`, `developers.google.com` и `myaccount.google.com`, пока они нужны только `data-ipc.js`, а тот открывает ссылку сам, без участия рендерера.

**(4) Горячие клавиши.** В `main.js` заменить `isValidAccelerator(v)` на `normalizeAccelerator(v) !== null` из `lib/settings-store.js`. Эта функция приводит регистр и синонимы к одному виду (`ctrl` → `Control`, `CmdOrCtrl` → `Control`) и отклоняет системные сочетания в любом написании. `saveSettings` уже нормализует сохранённые значения.

**(5) Проверка IPC.** На входе `widget:create/update/delete/move-item` и `set-completed` проверять:

- `listKind ∈ {tasks, habits}`;
- `taskId`, `parentId`, `previousId` — строки не длиннее 256 символов;
- `title` — не длиннее 1024, `notes` — не длиннее 8192;
- `orderedIds` — массив не длиннее 2000;
- `patch` — простой объект только с ключами `title/notes/due/dueTime/recurrence`.

В `google-tasks.updateItem` обрезать `title` и `notes` до разбора и передавать в `updateMockItem` уже обрезанные `body.*`. Для `widget:import-client-json` взять `readFileCapped()` из `lib/storage-backup.js` и не принимать UNC-пути (`\\server\…`).

**(6) Автозапуск.**

```js
const quoted = `"${process.execPath}"`;
if (app.isPackaged) app.setLoginItemSettings({ openAtLogin, path: quoted });
```

В dev-режиме `setLoginItemSettings` не вызывать совсем: сейчас он стирает или перехватывает запись установленного виджета, потому что имя значения одно и то же, `com.glasstasks.widget`. Вызывать `setLoginItemSettings` только при изменении настройки, а не при каждом запуске. Сейчас каждый запуск удаляет `StartupApproved\Run` и тем самым снова включает автозапуск, который пользователь выключил в «Диспетчере задач».

**(7) Обновления.** У обновлений нет корня доверия вне GitHub. Варианты:

- **A.** Подписывать установщик (Authenticode), прописать `win.publisherName` и удалить вводящие в заблуждение `verifyUpdateCodeSignature = false`.
- **B.** Без сертификата: встроить в приложение открытый ключ Ed25519. Офлайн, ключом вне GitHub и CI, подписывать **версию вместе с sha512** (иначе можно выдать старый подписанный установщик за новую версию). Выключить `autoInstallOnAppQuit` и вызывать `quitAndInstall` только после проверки подписи.

Канал обновлений перевести в публичный репозиторий только с релизами. Токены в конфигурацию публикации не встраивать.

**(8) Electron.** Перейти на поддерживаемую ветку Electron. Добавить Dependabot или Renovate для `electron`, `electron-updater`, `electron-builder` и в CI — проверку, что основная версия Electron ещё поддерживается. После перехода перепроверить fuses, кавычки в `Run` и поведение `file://`.

**(9) GitHub Actions.**

- Верхним уровнем `permissions: contents: read`.
- У `actions/checkout` — `persist-credentials: false`.
- Actions закрепить полными SHA.
- В CI — `npm ci --ignore-scripts`.
- В release: сборка только с правом чтения, публикация — отдельной задачей с `environment` и обязательным подтверждением.

**(10) Loopback-сервер входа.** Отклонять запросы, у которых `Host` не равен `127.0.0.1:<port>`. В ответы добавить `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`.

**(11) Дочерние процессы Windows.**

```js
const SYS32 = path.join(process.env.SystemRoot || 'C:\\Windows', 'System32');
execFile(path.join(SYS32, 'WindowsPowerShell', 'v1.0', 'powershell.exe'), args, { cwd: SYS32, … });
execFileSync(path.join(SYS32, 'reg.exe'), args, { cwd: SYS32, timeout: 4000, windowsHide: true });
```

**(12) Установщик и прочее.**

- `nsis.allowToChangeInstallationDirectory: false`: тогда установка всегда идёт в `%LOCALAPPDATA%\Programs`, куда может писать только сам пользователь. Уже установленные копии в другой папке так не мигрируют; это стоит проверять в `customInit`.
- Обои: сначала брать `TranscodedWallpaper`, UNC-пути пропускать, файлы больше ~25 МБ не декодировать.
- В `update-desktop-shortcut.ps1` вместо `npx --yes electron` вызывать `node_modules\.bin\electron.cmd`.

**(13) Логгер (prod-readiness).** В шаблоны редактирования добавить `1%2[Ff]%2[Ff][0-9A-Za-z_-]{20,}` и параметр `[?&]token=`. Источник утечки в `google-auth.js` уже закрыт, это защита на будущее. В `diagnostics.js` путь к данным выводить через `displayPath()` из `lib/storage-status.js`: имя пользователя бывает и в UNC-путях перенаправленных профилей.

**(14) Статус отзыва при выходе.** `widget:logout` и `storeCredentials` должны возвращать или показывать результат `revokeAndClearTokens()`: при `failed`/`locked` нужно окно со ссылкой на https://myaccount.google.com/permissions, как в `data:wipe-all` (`electron/data-ipc.js`).

## Второй раунд: проверка самих исправлений

Все исправления первого раунда снова прошли через четырёх независимых ревьюеров с воспроизведением в Electron 33. Найдено и исправлено:

- **История привычек могла пропасть при неверных часах ПК.** Новое окно дат применялось к своему `streaks.json`: при запуске с отставшими часами вся история считалась «будущей». Теперь окно дат действует только при импорте, а лимит хранения — это 120 последних месяцев с отметками, без опоры на часы. Тесты гоняют часы на 5 лет назад и на 15 лет вперёд.
- **Каналы `data:*` отклоняли собственное окно, если в пути установки есть `~`, `[`, `]` или `%`** (8.3-имена вроде `ADMINI~1`, папка `Programs [x64]`). Теперь сравнение устойчиво к экранированию.
- **Отзыв токена считался успешным при любом HTTP 400**, в том числе при отказе прокси. Теперь успехом считается только `invalid_token` от Google. Нечитаемый файл токена даёт статус `locked`, а не «нечего отзывать».
- **Чистка секретов в экспорте правила уже сериализованный JSON.** Это могло испортить файл и пропустить токен в начале строки лога. Теперь чистятся исходные строки, а готовый текст проверяется разбором. Общие шаблоны применяются только к логам и больше не портят заметки в CSV.
- **Win/AltGr в горячих клавишах Electron 33 на Windows теряет**: `Win+A` регистрировался как `A`. Такие сочетания больше не принимаются. Зато принимаются `Plus`, клавиши громкости и мультимедиа, знаки пунктуации (``Control+` ``) и модификаторы в любом порядке. Непринятое изменение оставляет текущее сочетание и показывает предупреждение.
- **Удаление данных** теперь находит и составные копии (`.bak.corrupt-*`, `.bak.*.tmp`), повторяет попытку для занятых файлов, не обрывается на нечитаемой папке `backups`.
- **Хранилище**: `.bak` при блокировке тоже читается с повторами; конверт шифрования распознаётся разбором JSON; сбой шифрования не всплывает из `read()`; при старте удаляются `.corrupt`-копии секретов от старых версий. Лишняя `.unread`-копия больше не делается только для `reminders.json`, который перечитывается перед каждой записью. Для настроек и истории привычек защита остаётся и после успешного повторного чтения: их хранилища держат в памяти значения по умолчанию, полученные, пока файл был занят, и без защиты затёрли бы настоящий файл. Этот сценарий потери данных нашёл один из верификаторов.
- **Регулярное выражение CSV** было квадратичным на длинных сериях табуляций.
- **Тесты больше не зависят от реальной даты**: тест импорта сломался бы 31.12.2026.
